# Проверка новых юзернеймов Telegram-ботов

Python 3.10+. Скрипт перебирает названия компаний и известные короткие написания,
добавляет `agent`, `ai`, `app`, `game`, `gay`, `bot` и проверяет доступность через MTProto.
Для каждого суффикса по умолчанию формируются оба варианта: слитно и с
подчёркиванием. Например: `appleagent` и `apple_agent`, `appleai` и `apple_ai`,
`appleapp` и `apple_app`, `applegame` и `apple_game`, `applegay` и `apple_gay`,
`applebot` и `apple_bot`.

Для новых суффиксов используется **`bots.checkUsername(additional=True)`** из
актуальной схемы TDLib. Для `bot` и `_bot` используется обычная проверка имени
бота (без флага `additional`). Скрипт только проверяет имена: не создаёт ботов, не регистрирует
юзернеймы и не отправляет сообщения BotFather.

## Быстрый запуск

Распакуйте архив и откройте терминал в папке `telegram_name_checker`.

```bash
python -m venv .venv
# macOS / Linux:
source .venv/bin/activate
# Windows PowerShell вместо предыдущей строки:
# .venv\Scripts\Activate.ps1

python -m pip install -r requirements.txt
```

Получите свои `api_id` и `api_hash` на https://my.telegram.org/apps.
Это реквизиты приложения Telegram API, а не токен бота.

macOS / Linux:

```bash
export TG_API_ID='123456'
export TG_API_HASH='YOUR_32_CHARACTER_API_HASH'
python check_names.py --limit 25
```

Windows PowerShell:

```powershell
$env:TG_API_ID = '123456'
$env:TG_API_HASH = 'YOUR_32_CHARACTER_API_HASH'
python check_names.py --limit 25
```

При первом запуске Telethon запросит номер телефона, код входа и пароль 2FA,
если он включён. Вход выполняется в пользовательский аккаунт. Для новых
дополнительных имён требуется Telegram Premium; сервер проверяет права аккаунта.
Обычные имена с `bot` и `_bot` можно проверять отдельно без Premium:
`python check_names.py --suffixes bot`.
Реквизиты вводите у себя локально. Файлы `private/*.session*` содержат доступ
к аккаунту: не передавайте их и не добавляйте в репозиторий.

Полная проверка:

```bash
python check_names.py
```

Остановка — `Ctrl+C`. Повторите ту же команду для продолжения. После пробного
запуска с `--limit 25` можно запустить команду без лимита: первые результаты
будут взяты из кэша, остальные имена будут проверены.

## Что входит в список

- `sources/global_companies.csv`: 828 компаний, дочерних компаний и брендов
  из разных стран, включая российские названия, с ручными алиасами.
- `sources/sp500.csv`: снимок 503 строк состава S&P 500; некоторые компании
  представлены несколькими классами акций. Дата получения и источник
  записаны в `sources/metadata.json`.
- `sources/russian_companies.csv`: 1 070 названий российских компаний,
  локальных брендов и сервисов с латинскими алиасами: банки, промышленность,
  IT, торговля, транспорт, застройщики, медицина, образование и другие отрасли.
  Это ручной список кандидатов, включая исторические названия, а не реестр
  юридических лиц и не подтверждение текущего владельца бренда.
- `sources/moex_companies.csv`: 229 эмитентов из MOEX ISS, с уникальным
  российским ИНН из 10 цифр и торгующимися обыкновенными/привилегированными
  акциями. Данные и дата получения — в `sources/metadata.json`.
  Это выборка эмитентов, а не рейтинг по размеру бизнеса.
- `candidates_preview.csv`: 36 774 уникальных кандидата, заранее сформированных
  с шестью суффиксами в двух форматах. **Их доступность ещё не проверена.**

Список даёт широкий стартовый охват, но не является мировым рейтингом и не
гарантирует покрытие всех крупных компаний. Источник S&P 500 поддерживается
сообществом, а не S&P. В ручном списке могут оставаться исторические бренды.
Названия, совпавшие после нормализации, объединяются с сохранением источников.
Короткие биржевые тикеры автоматически не добавляются.

Снимки входят в архив: доступ к сайтам со списками для обычного запуска не нужен.
Все четыре списка включены в обычный запуск `python check_names.py`.
Для обновления состава S&P 500:

```bash
python check_names.py --refresh-sources --dry-run
```

Этой командой обновляется только S&P 500. Российские CSV — сохранённые снимки
и ручные списки; их можно редактировать отдельно.

## Результаты

Всё записывается в `output/`:

| Файл | Содержимое |
| --- | --- |
| `available.txt` | По одному `@username` на строку, сервер ответил `True` на подходящую проверку имени бота |
| `available.csv` | Те же имена с компанией, ссылкой, суффиксом и временем проверки |
| `results.csv` | Все кандидаты выбранного прохода, включая занятые, ошибки и ещё не проверенные |
| `candidates.csv` | Все сгенерированные кандидаты выбранного прохода |
| `skipped.csv` | Варианты, исключённые локальной проверкой формата |
| `state.sqlite3` | Сохранённые проверки и обязательные паузы для продолжения |
| `namespace_available.csv` | Только результаты дополнительного режима `namespace` |

Проверка каждого имени сразу сохраняется в SQLite. CSV и TXT обновляются
каждые 25 проверок и при штатном завершении или `Ctrl+C`.
После аварийного завершения экспорт можно восстановить без сети:

```bash
python check_names.py --export-only
```

Используйте тот же список компаний, суффиксы и `--out`, чтобы восстановить
тот же набор результатов. Не запускайте два процесса с одним `--out` или
одним файлом сессии одновременно.

Основные статусы: `available`, `occupied`, `unavailable`, `purchase_required`,
`reserved`, `invalid`, `unsupported_suffix`, `account_limited`, `error`, `unknown`,
`pending`, `stale`.
Имена на Fragment не считаются свободными. Ошибки и неизвестные ответы также
никогда не попадают в `available.txt`.

`available` означает положительный ответ сервера **на момент проверки**.
До регистрации имя может занять другой пользователь. Окончательное назначение
в BotFather зависит также от правил Telegram, а для новых суффиксов —
от Premium и текущего лимита дополнительных имён.
Число «два бота» в скрипт не зашито.

## Свой список и настройки

Свой TXT: одно название в строке. Свой CSV: столбец `company`, `name` или
`Security`; необязательный `aliases` содержит варианты через `;`.
Пример есть в `companies_example.csv`.

```bash
# Только собственный список:
python check_names.py --companies companies_example.csv

# Только ручной российский список с латинскими алиасами:
python check_names.py --companies sources/russian_companies.csv

# Только обычные bot и _bot:
python check_names.py --suffixes bot

# Только конкретные названия:
python check_names.py --company Apple --company Microsoft --company Yandex

# По умолчанию — оба варианта: appleai и apple_ai:
python check_names.py

# Только слитные варианты, если они нужны отдельно:
python check_names.py --no-underscore

# Только выбранные суффиксы:
python check_names.py --suffixes ai agent app

# Без Telegram, зависимостей и авторизации — сформировать кандидатов:
python check_names.py --dry-run

# Повторно проверить даже свежие результаты:
python check_names.py --recheck

# Медленнее, с другой папкой результатов:
python check_names.py --delay 5 --jitter 1 --out my_results
```

Кириллица транслитерируется, но для точного брендового написания лучше задать
алиас (`Яндекс` → `yandex`, `Сбербанк` → `sber`). Юридические окончания и пометки
классов акций удаляются. Слишком длинные имена не обрезаются; некорректные
варианты пропускаются. Имена, начинающиеся с цифры, тоже пропускаются.
Варианты с подчёркиванием включены по умолчанию. Флаг `--no-underscore`
отключает их и сокращает время полного прохода примерно вдвое.

## Паузы, кэш и совместимость

Запросы выполняются последовательно: интервал по умолчанию не менее 3 секунд
плюс случайные 0–0,5 секунды. Для 36 774 кандидатов это примерно 33,2 часа
плюс сеть и `FLOOD_WAIT`; фиксированный интервал не гарантирует отсутствие
ограничений Telegram.

Если сервер вернул `FLOOD_WAIT`, скрипт сохраняет обязательную паузу и соблюдает
её, в том числе после перезапуска. Паузы более 300 секунд по умолчанию приводят
к выходу; повторный запуск до истечения паузы не отправит проверочный запрос.
Порог ожидания можно поменять: `--max-flood-wait 3600`.

Результаты используются из кэша 72 часа (`--cache-hours 72`), чтобы вмещать
расширенный полный проход по спискам. Просроченные
результаты получают `stale` и исключаются из списка свободных. Для короткого
списка можно поставить меньший срок; для прохода на несколько часов выбирайте
срок кэша длиннее ожидаемой длительности проверки. Ошибки не кэшируются
для пропуска при следующем запуске.

Новая схема содержит `bots.checkUsername#e3ac4c61` с флагом `additional`.
Telethon 1.45.0 пока содержит прежний вариант метода, поэтому скрипт включает
минимальную реализацию нового запроса для дополнительных имён. Для `bot` и
`_bot` используется штатный обычный запрос Telethon. Если установленная версия
Telethon уже поддерживает `additional`, используется её реализация с подходящим
значением флага. Если сервер ещё
не принимает метод или требуется Premium, скрипт
останавливается с причиной. Пять ошибок подряд или пять отклонений суффикса
подряд тоже останавливают проход.

### Если получен OWNER_USERNAMES_LIMIT_EXCEEDED

Ответ сохраняется **только для того юзернейма, который вернул ошибку**:
статус `account_limited`, точная причина и время запроса попадают в `results.csv`.
Этот статус не означает, что имя свободно или занято. Скрипт сразу переходит
к следующему кандидату и продолжает проверку всех суффиксов. Даже несколько
таких отказов подряд не отключают группу и не останавливают проход.

При повторном запуске конкретное имя с этим ответом пропускается на срок
кэша (по умолчанию 72 часа), как и другие сохранённые результаты.
Чтобы повторить запросы к таким именам раньше истечения кэша:

```bash
python check_names.py --retry-additional
```

Флаг повторно проверяет только сохранённые `account_limited`, добавляя их
к ещё не проверенным кандидатам; остальные свежие результаты остаются в кэше.
`--recheck` повторяет все проверки. Если в проходе встретился такой отказ,
код завершения равен 2: очередь обработана, но для части имён доступность
осталась неизвестной.

Записанные прежней версией отметки блокировки группы **больше не используются**.
Непроверенные из-за старой отметки имена автоматически возвращаются в очередь.
Статус `account_limited` в новом экспорте имеют только имена, на которые был
получен реальный отказ. Прочие ещё не проверенные имена имеют `pending`.

Для обновления скрипта замените `check_names.py` файлом из нового архива
в существующей папке. Сохраните `output/state.sqlite3` и папку `private`.
Старая база результатов совместима; CSV/TXT не заменяют базу прогресса.
Повторные проверки обычных результатов выполняются после истечения срока
кэша, при `--recheck`, после ответа `error`/`unknown`, при смене `--mode`
или при использовании другого `--out` без прежней базы.
Если предыдущий процесс ещё работает, сначала остановите его через `Ctrl+C`,
а после замены файла запустите скрипт снова.

Для проверки гипотезы об ограничении сравнивайте следующие ответы после
`OWNER_USERNAMES_LIMIT_EXCEEDED` в консоли или `results.csv`: сохраняются
конкретный юзернейм, суффикс, время, статус и точная причина. Скрипт не делает
вывод о доступности остальных имён по одному отказу.

Для диагностики доступен отдельный режим:

```bash
python check_names.py --mode namespace --limit 25
```

Он использует `account.checkUsername` и показывает только доступность в общем
пространстве имён. Его положительные ответы записываются со статусом
`namespace_available` в отдельный CSV и **не подтверждают пригодность для бота**.
Автоматического переключения на этот режим нет.

## Проверка кода

```bash
python -m unittest discover -s tests -v
```

16 тестов проверяют формирование кандидатов, новый формат MTProto-запроса,
обработку ответов и ошибок, обязательные паузы, кэш, продолжение и экспорт,
а также продолжение всех суффиксов после единичных и повторных отказов,
кэш отказов по конкретному имени, игнорирование прежней блокировки группы,
сохранение старых результатов и точечный повтор запросов по флагу.
Проверено на Python 3.12 и Telethon 1.45.0. Реальный массовый проход
в Telegram не выполнялся: для него нужна ваша локальная авторизация.
