# Проверка новых юзернеймов Telegram-ботов

Python 3.10+. Скрипт перебирает названия компаний и известные короткие написания,
добавляет `agent`, `ai`, `app`, `game`, `gay`, `bot` и проверяет доступность через MTProto.
Для каждого суффикса по умолчанию формируются оба варианта: слитно и с
подчёркиванием. Например: `appleagent` и `apple_agent`, `appleai` и `apple_ai`,
`appleapp` и `apple_app`, `applegame` и `apple_game`, `applegay` и `apple_gay`,
`applebot` и `apple_bot`.

Для новых суффиксов используется **`bots.checkUsername(additional=True)`** из
актуальной схемы TDLib. Для `bot` и `_bot` используется обычная проверка имени
бота (без флага `additional`). Скрипт только проверяет имена: не создаёт ботов, не регистрирует
юзернеймы и не отправляет сообщения BotFather.

## Сайт и постоянная проверка через Docker

В проект входят сайт на русском языке, reverse proxy Caddy и отдельный фоновый обработчик `worker`.
Для внешнего reverse proxy предусмотрен [вариант запуска без Caddy](#запуск-без-caddy-с-внешним-reverse-proxy).
Сайт читает общую SQLite-базу: поиск по имени/компании, фильтры статуса и суффикса,
сортировка, страницы, копирование имени, экспорт CSV/TXT, состояние обработчика
и ближайшие имена в очереди. Данные автоматически обновляются каждые 15 секунд.
По умолчанию показаны только `available`, проверенные менее 72 часов назад.
Результаты `namespace` не считаются свободными именами ботов и на сайте не показываются.

Понадобится Docker с командой `docker compose` (на Windows — Docker Desktop
с Linux-контейнерами). Все команды выполняются в папке проекта.

1. При первом запуске создайте `.env` из примера:

   ```powershell
   Copy-Item .env.example .env
   ```

   На Linux/macOS: `cp .env.example .env`. Если `.env` уже есть, отредактируйте его.
   Впишите `TG_API_ID` и `TG_API_HASH` с https://my.telegram.org/apps.

2. Соберите образ и авторизуйте Telegram-сессию:

   ```bash
   docker compose build
   docker compose run --rm login
   ```

   Введите телефон, код и пароль 2FA, если включён. Этот режим только выполняет вход,
   имена не проверяет. Если `private/checker.session` уже авторизован, вход можно пропустить.
   Перед повторным входом остановите обработчик: `docker compose stop worker`.

3. Запустите Caddy, сайт и обработчик:

   ```bash
   docker compose up -d caddy worker
   ```

   Откройте **http://localhost:8080**. Просмотр сайта работает и без авторизации:
   `docker compose up -d caddy` запустит сайт и покажет сохранённые результаты и непроверенные имена.
   Сервис `web` запускается как зависимость; Caddy дожидается его готовности.

Управление:

```bash
docker compose logs -f worker       # ход проверок и ошибки Telegram
docker compose logs -f caddy        # состояние reverse proxy и сертификатов
docker compose ps                   # состояние сервисов
docker compose down                 # остановить; результаты и сессия сохранятся
docker compose up -d --build         # пересобрать и запустить после обновления кода
```

`output/` и `private/` подключены с компьютера, поэтому существующая база
`output/state.sqlite3` продолжает использоваться и сохраняется после пересоздания
контейнеров. Telegram-сессия доступна только обработчику и сервису входа;
в образ и сервис сайта она не попадает. Сайт выдаёт только интерфейс и API результатов.
По умолчанию порт доступен только на этом компьютере (`WEB_HOST=127.0.0.1`).
В стандартном варианте внешние запросы принимает Caddy и передаёт в `web:8080` по сети Compose;
у `web` нет опубликованного порта. Конфигурация находится в `Caddyfile`.

### Домен и HTTPS через Caddy

По умолчанию `CADDY_SITE_ADDRESS=:80`: Caddy обслуживает локальный HTTP
на http://localhost:8080. Для публичного домена направьте DNS A/AAAA на сервер,
откройте входящие TCP-порты 80 и 443 и задайте в `.env`:

```dotenv
WEB_HOST=0.0.0.0
WEB_PORT=80
WEB_HTTPS_PORT=443
CADDY_SITE_ADDRESS=names.example.com
```

Замените `names.example.com` своим доменом без `https://`, затем выполните
`docker compose up -d`. Caddy автоматически выпустит и будет обновлять
TLS-сертификат, а HTTP перенаправит на HTTPS. UDP-порт 443 используется для HTTP/3;
для обычного HTTPS достаточно TCP. Подробнее: [Automatic HTTPS](https://caddyserver.com/docs/automatic-https).
Каталог сайта и результаты станут доступны посетителям этого домена.
Сертификаты и состояние Caddy хранятся в постоянных томах `caddy_data` и `caddy_config`,
которые сохраняются после обычного `docker compose down`.

Проверить конфигурацию и применить изменение `Caddyfile` без остановки прокси:

```bash
docker compose run --rm --no-deps caddy caddy validate --config /etc/caddy/Caddyfile --adapter caddyfile
docker compose exec caddy caddy reload --config /etc/caddy/Caddyfile --adapter caddyfile
```

После изменения переменных `.env` используйте `docker compose up -d`:
они передаются контейнеру при его создании.

### Запуск без Caddy с внешним reverse proxy

Если Nginx, Traefik или другой reverse proxy уже настроен, используйте дополнительный
файл `compose.external-proxy.yaml`. Он отключает автозапуск Caddy через профиль
`bundled-proxy` и публикует HTTP-порт сервиса `web` напрямую.
Создание `.env`, сборка и авторизация Telegram выполняются как в шагах 1–2 выше.

Для прокси на том же сервере задайте в `.env`:

```dotenv
WEB_HOST=127.0.0.1
WEB_PORT=8080
```

Если Caddy из этого проекта уже запущен, сначала остановите его, чтобы освободить порт:

```bash
docker compose stop caddy
```

Запустите сайт и обработчик:

```bash
docker compose -f compose.yaml -f compose.external-proxy.yaml up -d --build
```

Для просмотра сайта без обработчика добавьте `web` в конец команды.
Сайт доступен по HTTP на `127.0.0.1:8080`; проверка готовности — `/healthz`.
Настройте внешний прокси на этот адрес. Например, в существующем блоке `server`
Nginx для вашего домена:

```nginx
location / {
    proxy_pass http://127.0.0.1:8080;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
}
```

Домен, HTTPS-сертификаты и перенаправление HTTP на HTTPS настраиваются на внешнем прокси.
`WEB_HTTPS_PORT` и `CADDY_SITE_ADDRESS` в этом режиме не используются.
Если прокси работает на другом сервере, задайте `WEB_HOST` равным доступному ему IP-адресу
сервера приложения и разрешите доступ к `WEB_PORT` только от прокси.
Для прокси в контейнере `127.0.0.1` указывает на сам контейнер: подключите его
к сети Compose `<имя-проекта>_default` и используйте upstream `http://web:8080`.

Для обновления и управления этим вариантом всегда указывайте оба Compose-файла:

```bash
docker compose -f compose.yaml -f compose.external-proxy.yaml logs -f web worker
docker compose -f compose.yaml -f compose.external-proxy.yaml ps
docker compose -f compose.yaml -f compose.external-proxy.yaml up -d --build
docker compose -f compose.yaml -f compose.external-proxy.yaml down
```

### Как работает циклическая очередь

Сначала проверяются имена без результата. Затем берётся самая старая проверка
по `checked` из SQLite. После каждого ответа результат и новое время сразу
сохраняются в базе, а имя переходит в конец очереди. После последнего имени
начинается следующий круг. Повторный запуск восстанавливает порядок из базы,
старый кэш не исключает имена из циклической очереди. Перепроверяются все статусы,
включая занятые, свободные и ошибки; прежнее `available` заменяется новым ответом.

Обработчик выдерживает интервал не менее 3 секунд между запросами и все паузы
`FLOOD_WAIT`, включая длительные и сохранённые до перезапуска. При проблемах сети
или API он повторяет подключение после паузы. Без готовой сессии он показывает
ошибку и ожидает повторного подключения, не запрашивая код в фоне.
Один процесс проверки получает блокировки папки результатов и файла сессии;
параллельный запуск другого экземпляра с теми же ресурсами отклоняется.
Обычный скрипт старой версии перед запуском сервиса нужно остановить.

Настройки в `.env` (после изменения выполните `docker compose up -d`;
для внешнего прокси добавьте `-f compose.yaml -f compose.external-proxy.yaml` перед `up`):

| Переменная | По умолчанию | Значение |
| --- | --- | --- |
| `WEB_PORT` | `8080` | Внешний HTTP-порт Caddy или `web` в режиме внешнего прокси |
| `WEB_HTTPS_PORT` | `8443` | Только Caddy: внешний HTTPS-порт (TCP/UDP) |
| `WEB_HOST` | `127.0.0.1` | Адрес публикации портов Caddy или `web` в режиме внешнего прокси |
| `CADDY_SITE_ADDRESS` | `:80` | Только Caddy: локальный HTTP либо домен для автоматического HTTPS |
| `TG_PROXY` | пусто | SOCKS5-прокси для Telegram: `socks5://[user:password@]host:port` |
| `CHECK_DELAY` | `3` | Минимальная пауза между запросами, не менее 3 с |
| `CHECK_JITTER` | `0.5` | Дополнительная случайная пауза, с |
| `RECHECK_HOURS` | `0` | Минимальный возраст повторной проверки; 0 — непрерывные круги |
| `CACHE_HOURS` | `72` | Возраст, после которого результат считается устаревшим на сайте/в экспорте |
| `RETRY_DELAY` | `300` | Пауза после ошибок подключения или остановки из-за ошибок API, с |

При большом каталоге один круг может занимать больше `RECHECK_HOURS`.
Настройка не обещает точного расписания: действуют длина очереди и ограничения Telegram.

### Запуск сайта и очереди без Docker

После установки Python-зависимостей из раздела ниже:

```bash
python web_server.py
```

Откройте http://localhost:8080. Для другого порта: `python web_server.py --port 8090`.
При первом запуске сайт переносит метаданные из `output/candidates.csv`,
если файл есть; иначе создаёт каталог из встроенных списков. Результаты берёт
из прежней SQLite-базы. Новые запуски обработчика обновляют состав каталога
согласно выбранным компаниям/суффиксам; сохранённые проверки из базы не удаляются.

В другом терминале задайте `TG_API_ID`/`TG_API_HASH` (как в разделе ниже), затем:

```bash
python check_names.py --login-only
python check_names.py --watch --non-interactive
```

Для другого набора имён используются прежние параметры, например:

```bash
python check_names.py --watch --non-interactive --suffixes bot --recheck-hours 24
```

В Docker состав кандидатов можно переопределить командой `worker.command`
в `compose.yaml`, сохранив флаги `--watch --non-interactive`.
Для своего CSV/TXT дополнительно подключите файл в `worker.volumes` и передайте
его контейнерный путь через `--companies`.
При другом `--out` укажите ту же папку в `python web_server.py --out ...`.
Согласуйте `--cache-hours` сайта и обработчика. Остановка — `Ctrl+C`;
Docker также корректно завершает обработчик по `SIGTERM` с финальным экспортом.

API только для чтения:

```text
GET /healthz
GET /api/names?status=available&q=apple&suffix=bot&sort=newest&page=1&per_page=50
GET /api/export?status=available&format=csv
GET /api/export?status=available&format=txt
```

Экспорт применяет текущие фильтры ко всем найденным строкам, без ограничения страницей.
Доступные сортировки: `newest`, `oldest`, `username`, `company`; `status=all`
показывает все статусы. Положительный ответ `namespace` никогда не становится `available`.

## Быстрый запуск

Распакуйте архив и откройте терминал в папке `telegram_name_checker`.

```bash
python -m venv .venv
# macOS / Linux:
source .venv/bin/activate
# Windows PowerShell вместо предыдущей строки:
# .venv\Scripts\Activate.ps1

python -m pip install -r requirements.txt
```

Получите свои `api_id` и `api_hash` на https://my.telegram.org/apps.
Это реквизиты приложения Telegram API, а не токен бота.

macOS / Linux:

```bash
export TG_API_ID='123456'
export TG_API_HASH='YOUR_32_CHARACTER_API_HASH'
python check_names.py --limit 25
```

Windows PowerShell:

```powershell
$env:TG_API_ID = '123456'
$env:TG_API_HASH = 'YOUR_32_CHARACTER_API_HASH'
python check_names.py --limit 25
```

При первом запуске Telethon запросит номер телефона, код входа и пароль 2FA,
если он включён. Вход выполняется в пользовательский аккаунт. Для новых
дополнительных имён требуется Telegram Premium; сервер проверяет права аккаунта.
Обычные имена с `bot` и `_bot` можно проверять отдельно без Premium:
`python check_names.py --suffixes bot`.
Реквизиты вводите у себя локально. Файлы `private/*.session*` содержат доступ
к аккаунту: не передавайте их и не добавляйте в репозиторий.

Полная проверка:

```bash
python check_names.py
```

Остановка — `Ctrl+C`. Повторите ту же команду для продолжения. После пробного
запуска с `--limit 25` можно запустить команду без лимита: первые результаты
будут взяты из кэша, остальные имена будут проверены.

## Внешний SOCKS5-прокси для Telegram

Прокси задаётся флагом `--proxy` или переменной окружения `TG_PROXY`.
Поддерживаются подключения без авторизации и с логином/паролем:

```bash
python check_names.py --proxy 'socks5://proxy.example.com:1080' --limit 25
python check_names.py --proxy 'socks5://user:password@proxy.example.com:1080' --login-only
```

Для постоянной настройки в PowerShell:

```powershell
$env:TG_PROXY = 'socks5://user:password@proxy.example.com:1080'
python check_names.py --watch --non-interactive
```

На Linux/macOS: `export TG_PROXY='socks5://user:password@proxy.example.com:1080'`.
Флаг `--proxy` имеет приоритет над `TG_PROXY`; `--proxy ''` отключает прокси
для конкретного запуска. Без настройки используется прямое подключение.
Порт обязателен. Для IPv6 используйте скобки: `socks5://[2001:db8::1]:1080`.
Спецсимволы в логине/пароле кодируйте как в URL: `@` → `%40`, `:` → `%3A`,
`#` → `%23`, `$` → `%24`, `%` → `%25`.
Также принимается схема `socks5h://`; обе схемы используют `rdns=True`.

Для Docker впишите в `.env`:

```dotenv
TG_PROXY=socks5://user:password@proxy.example.com:1080
```

Затем выполните `docker compose build` и `docker compose up -d worker`.
Настройка автоматически передаётся и в `docker compose run --rm login`.
При запуске без Docker `.env` автоматически не читается: задайте переменную
в терминале или используйте флаг. После обновления установите зависимости:
`python -m pip install -r requirements.txt`.

Прокси применяется ко всем соединениям Telethon: входу, проверкам и повторным
подключениям. При недоступности прокси запросы завершаются ошибкой;
автоматического перехода на прямое подключение нет. Обновление списка
S&P 500 через `--refresh-sources` использует прежнее HTTP-подключение.
Формат настройки соответствует [документации Telethon](https://docs.telethon.dev/en/stable/basic/signing-in.html#signing-in-behind-a-proxy).

## Что входит в список

- `sources/global_companies.csv`: 828 компаний, дочерних компаний и брендов
  из разных стран, включая российские названия, с ручными алиасами.
- `sources/sp500.csv`: снимок 503 строк состава S&P 500; некоторые компании
  представлены несколькими классами акций. Дата получения и источник
  записаны в `sources/metadata.json`.
- `sources/russian_companies.csv`: 1 070 названий российских компаний,
  локальных брендов и сервисов с латинскими алиасами: банки, промышленность,
  IT, торговля, транспорт, застройщики, медицина, образование и другие отрасли.
  Это ручной список кандидатов, включая исторические названия, а не реестр
  юридических лиц и не подтверждение текущего владельца бренда.
- `sources/moex_companies.csv`: 229 эмитентов из MOEX ISS, с уникальным
  российским ИНН из 10 цифр и торгующимися обыкновенными/привилегированными
  акциями. Данные и дата получения — в `sources/metadata.json`.
  Это выборка эмитентов, а не рейтинг по размеру бизнеса.
- `candidates_preview.csv`: 36 774 уникальных кандидата, заранее сформированных
  с шестью суффиксами в двух форматах. **Их доступность ещё не проверена.**

Список даёт широкий стартовый охват, но не является мировым рейтингом и не
гарантирует покрытие всех крупных компаний. Источник S&P 500 поддерживается
сообществом, а не S&P. В ручном списке могут оставаться исторические бренды.
Названия, совпавшие после нормализации, объединяются с сохранением источников.
Короткие биржевые тикеры автоматически не добавляются.

Снимки входят в архив: доступ к сайтам со списками для обычного запуска не нужен.
Все четыре списка включены в обычный запуск `python check_names.py`.
Для обновления состава S&P 500:

```bash
python check_names.py --refresh-sources --dry-run
```

Этой командой обновляется только S&P 500. Российские CSV — сохранённые снимки
и ручные списки; их можно редактировать отдельно.

## Результаты

Всё записывается в `output/`:

| Файл | Содержимое |
| --- | --- |
| `available.txt` | По одному `@username` на строку, сервер ответил `True` на подходящую проверку имени бота |
| `available.csv` | Те же имена с компанией, ссылкой, суффиксом и временем проверки |
| `results.csv` | Все кандидаты выбранного прохода, включая занятые, ошибки и ещё не проверенные |
| `candidates.csv` | Все сгенерированные кандидаты выбранного прохода |
| `skipped.csv` | Варианты, исключённые локальной проверкой формата |
| `state.sqlite3` | Сохранённые проверки и обязательные паузы для продолжения |
| `namespace_available.csv` | Только результаты дополнительного режима `namespace` |

Проверка каждого имени сразу сохраняется в SQLite. CSV и TXT обновляются
каждые 25 проверок и при штатном завершении или `Ctrl+C`.
После аварийного завершения экспорт можно восстановить без сети:

```bash
python check_names.py --export-only
```

Используйте тот же список компаний, суффиксы и `--out`, чтобы восстановить
тот же набор результатов. Не запускайте два процесса с одним `--out` или
одним файлом сессии одновременно.

Основные статусы: `available`, `occupied`, `unavailable`, `purchase_required`,
`reserved`, `invalid`, `unsupported_suffix`, `account_limited`, `error`, `unknown`,
`pending`, `stale`.
Имена на Fragment не считаются свободными. Ошибки и неизвестные ответы также
никогда не попадают в `available.txt`.

`available` означает положительный ответ сервера **на момент проверки**.
До регистрации имя может занять другой пользователь. Окончательное назначение
в BotFather зависит также от правил Telegram, а для новых суффиксов —
от Premium и текущего лимита дополнительных имён.
Число «два бота» в скрипт не зашито.

## Свой список и настройки

Свой TXT: одно название в строке. Свой CSV: столбец `company`, `name` или
`Security`; необязательный `aliases` содержит варианты через `;`.
Пример есть в `companies_example.csv`.

```bash
# Только собственный список:
python check_names.py --companies companies_example.csv

# Только ручной российский список с латинскими алиасами:
python check_names.py --companies sources/russian_companies.csv

# Только обычные bot и _bot:
python check_names.py --suffixes bot

# Только конкретные названия:
python check_names.py --company Apple --company Microsoft --company Yandex

# По умолчанию — оба варианта: appleai и apple_ai:
python check_names.py

# Только слитные варианты, если они нужны отдельно:
python check_names.py --no-underscore

# Только выбранные суффиксы:
python check_names.py --suffixes ai agent app

# Без Telegram, зависимостей и авторизации — сформировать кандидатов:
python check_names.py --dry-run

# Повторно проверить даже свежие результаты:
python check_names.py --recheck

# Медленнее, с другой папкой результатов:
python check_names.py --delay 5 --jitter 1 --out my_results
```

Кириллица транслитерируется, но для точного брендового написания лучше задать
алиас (`Яндекс` → `yandex`, `Сбербанк` → `sber`). Юридические окончания и пометки
классов акций удаляются. Слишком длинные имена не обрезаются; некорректные
варианты пропускаются. Имена, начинающиеся с цифры, тоже пропускаются.
Варианты с подчёркиванием включены по умолчанию. Флаг `--no-underscore`
отключает их и сокращает время полного прохода примерно вдвое.

## Паузы, кэш и совместимость

Запросы выполняются последовательно: интервал по умолчанию не менее 3 секунд
плюс случайные 0–0,5 секунды. Для 36 774 кандидатов это примерно 33,2 часа
плюс сеть и `FLOOD_WAIT`; фиксированный интервал не гарантирует отсутствие
ограничений Telegram.

Если сервер вернул `FLOOD_WAIT`, скрипт сохраняет обязательную паузу и соблюдает
её, в том числе после перезапуска. Паузы более 300 секунд по умолчанию приводят
к выходу; повторный запуск до истечения паузы не отправит проверочный запрос.
Порог ожидания можно поменять: `--max-flood-wait 3600`.

Результаты используются из кэша 72 часа (`--cache-hours 72`), чтобы вмещать
расширенный полный проход по спискам. Просроченные
результаты получают `stale` и исключаются из списка свободных. Для короткого
списка можно поставить меньший срок; для прохода на несколько часов выбирайте
срок кэша длиннее ожидаемой длительности проверки. Ошибки не кэшируются
для пропуска при следующем запуске.

Новая схема содержит `bots.checkUsername#e3ac4c61` с флагом `additional`.
Telethon 1.45.0 пока содержит прежний вариант метода, поэтому скрипт включает
минимальную реализацию нового запроса для дополнительных имён. Для `bot` и
`_bot` используется штатный обычный запрос Telethon. Если установленная версия
Telethon уже поддерживает `additional`, используется её реализация с подходящим
значением флага. Если сервер ещё
не принимает метод или требуется Premium, скрипт
останавливается с причиной. Пять ошибок подряд или пять отклонений суффикса
подряд тоже останавливают проход.

### Если получен OWNER_USERNAMES_LIMIT_EXCEEDED

Ответ сохраняется **только для того юзернейма, который вернул ошибку**:
статус `account_limited`, точная причина и время запроса попадают в `results.csv`.
Этот статус не означает, что имя свободно или занято. Скрипт сразу переходит
к следующему кандидату и продолжает проверку всех суффиксов. Даже несколько
таких отказов подряд не отключают группу и не останавливают проход.

При повторном запуске конкретное имя с этим ответом пропускается на срок
кэша (по умолчанию 72 часа), как и другие сохранённые результаты.
Чтобы повторить запросы к таким именам раньше истечения кэша:

```bash
python check_names.py --retry-additional
```

Флаг повторно проверяет только сохранённые `account_limited`, добавляя их
к ещё не проверенным кандидатам; остальные свежие результаты остаются в кэше.
`--recheck` повторяет все проверки. Если в проходе встретился такой отказ,
код завершения равен 2: очередь обработана, но для части имён доступность
осталась неизвестной.

Записанные прежней версией отметки блокировки группы **больше не используются**.
Непроверенные из-за старой отметки имена автоматически возвращаются в очередь.
Статус `account_limited` в новом экспорте имеют только имена, на которые был
получен реальный отказ. Прочие ещё не проверенные имена имеют `pending`.

Для обновления скрипта замените `check_names.py` файлом из нового архива
в существующей папке. Сохраните `output/state.sqlite3` и папку `private`.
Старая база результатов совместима; CSV/TXT не заменяют базу прогресса.
Повторные проверки обычных результатов выполняются после истечения срока
кэша, при `--recheck`, после ответа `error`/`unknown`, при смене `--mode`
или при использовании другого `--out` без прежней базы.
Если предыдущий процесс ещё работает, сначала остановите его через `Ctrl+C`,
а после замены файла запустите скрипт снова.

Для проверки гипотезы об ограничении сравнивайте следующие ответы после
`OWNER_USERNAMES_LIMIT_EXCEEDED` в консоли или `results.csv`: сохраняются
конкретный юзернейм, суффикс, время, статус и точная причина. Скрипт не делает
вывод о доступности остальных имён по одному отказу.

Для диагностики доступен отдельный режим:

```bash
python check_names.py --mode namespace --limit 25
```

Он использует `account.checkUsername` и показывает только доступность в общем
пространстве имён. Его положительные ответы записываются со статусом
`namespace_available` в отдельный CSV и **не подтверждают пригодность для бота**.
Автоматического переключения на этот режим нет.

## Проверка кода

```bash
python -m unittest discover -s tests -v
```

Тесты проверяют формирование кандидатов, новый формат MTProto-запроса,
обработку ответов и ошибок, обязательные паузы, кэш, продолжение и экспорт,
а также продолжение всех суффиксов после единичных и повторных отказов,
кэш отказов по конкретному имени, игнорирование прежней блокировки группы,
сохранение старых результатов и точечный повтор запросов по флагу.
Тесты сервиса дополнительно проверяют циклический порядок, восстановление очереди,
паузы, блокировки, неинтерактивный вход, фильтры сайта, устаревание результатов,
изоляцию `namespace`, HTTP-маршруты и экспорт без ограничения страницей.
Образ использует Python 3.12 и Telethon 1.45.0. Реальный массовый проход
в Telegram не выполнялся: для него нужна ваша локальная авторизация.
